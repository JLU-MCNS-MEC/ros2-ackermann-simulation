# 多传感器融合、视觉感知与语义导航实施方案

更新与开源资料核查日期：2026-09-10。范围：约 100 平方米室内 Ackermann 车辆。
本文包含实施计划与已验收的前置阶段；未勾选的融合、识别与三维能力仍未完成。

## 1. 建议结论与当前条件

采用渐进路线：保留当前二维导航闭环，先增加 RGB-D 障碍观测和物体定位，
再评估视觉/激光里程计与三维闭环，最后扩展开放词汇和关系语义导航。
不要同时更换定位器、建图器与控制器，否则性能变化难以归因。

当前已具备：轮式里程计 + IMU 的 EKF、激光二维建图与 AMCL、Nav2 安全控制链、
人工命名地标。视觉尚未参与自动物体识别或在线融合。

- RGB-D 模型：640 × 480、15 Hz、深度范围 0.2–8 m；室内启动默认关闭。
  已通过静止/运动各 120 s 的仿真质量检查；全天运行、遮挡和实际识别尚待验收。
- 激光模型：10 Hz、1024 × 20 采样；本次实际读取 `/scan/points` 字段为
  `x/y/z/intensity/ring`，没有逐点时间字段。它不是完整 Livox 扫描时序模型。
- IMU：100 Hz；仿真噪声、轮胎打滑与真实协方差仍需系统性退化测试。
- 本机 GPU：RTX 4060 Ti，约 8 GB 显存；同时运行 Gazebo 与视觉网络必须实测资源，
  不预设大型分割模型能实时运行。实车计算平台、相机与雷达型号尚未确认。
- 场景目前以简单几何和材质为主。预训练检测器在此域的识别效果不能直接假定；
  需补充真实外观资产、多视角标注和真实数据回放，真值只用于离线评估。

## 2. 三类融合分开实现

### A. 定位融合：车辆在哪里

1. 保留 `robot_localization` 融合编码器速度与 IMU 的基线。
2. RGB-D VO / ICP odometry 先在评估命名空间输出轨迹，不发布主 TF。
3. 对同一 rosbag 比较轮速 + IMU、视觉、激光和组合方案；按创新残差、协方差、
   延迟与健康状态门控，拒绝跳变、过期和低质量输入。
4. 不能把已经使用同一 IMU/轮速的 LIO、VIO 结果与原始输入当作独立观测重复融合。
   先选一个主局部估计器；如需组合，明确相关性处理和独立信息来源。
5. LIO/LIVO 专项必须先补逐点时间、运动去畸变、时钟同步和外参。
   不给当前瞬时点云伪造扫描时间以宣称通过真实 LIO 验收。

TF 发布权始终唯一：局部估计器发布 `odom -> base_footprint`；全局定位/SLAM
发布 `map -> odom`；RSP 发布车体与传感器 TF。二维和三维全局定位器不得同时接管。
估计器切换需处理参考原点、协方差与连续性，不能直接切换两个不同原点的 TF。

### B. 障碍融合：哪里可以走

激光与 RGB-D 分别进行时间检查、车体过滤、地面过滤和距离裁剪，然后以独立
观测源进入局部障碍层。保留来源与观测时间，不先简单拼接全部点云。

- RGB-D 补充近处桌腿、突出物和雷达盲区；有限视场不能替代环视雷达。
- 两种传感器的射线清除与障碍标记分开管理，避免相机空洞清掉雷达障碍。
- 无效深度、玻璃和黑色物体不是自由空间；必要时增加短距 ToF/超声与触碰保险杠。
- 动态物体进入短时障碍层；静态持久地图不无限保留移动行人。
- 语义可增加禁行/缓行成本，但不能把几何障碍因“识别为可通行”而删除。
- 保留 `Nav2 -> velocity_smoother -> Collision Monitor -> /cmd_vel_safe ->`
  `twist_to_ackermann -> /drive -> 底盘`，安全与控制不等待视觉模型推理。

### C. 语义融合：目标是什么、在哪里

第一版限定桌、椅、货架、门等类别。检测/分割得到区域后，用同步深度、有效像素
统计和采集时刻的 TF 投影到三维；拒绝背景混入、深度不足和大不确定度结果。
通过位置、几何重叠、类别与外观进行跨帧关联，不把每一帧创建为新物体。

物体记录至少包含：`object_id`、类别/别名、三维包围盒、位置不确定度、置信度、
观测次数、最后观测时间、数据来源、地图版本、关键帧关联及可达停靠候选。
人工记录继续保留 `manual_pose`，自动观测使用独立来源，不静默覆盖人工地标。

保存关键帧坐标下的观测，而非仅保存固定 `map` 坐标；闭环后按优化位姿重新融合。
地图哈希改变时，当前命名数据库需要显式迁移/重建，不能绕过现有地图一致性检查。

自然语言查询先解析为候选物体，再做歧义处理、路径可达性与朝向检查。导航目标
应是物体旁的可停靠位置，不是物体中心；接近后再观测确认，目标移动则重规划。
大模型不得直接输出底盘命令，未知或歧义目标不得随意选一个执行。

### D. 端到端视觉导航：图像如何直接生成动作

目标接口为 `当前/历史 RGB 图像 + 相对目标或目标图像 -> 线速度与角速度`。第一阶段用
Nav2 产生安全示范，并让视觉模型在影子模式同步预测；模型输出只进入独立话题，不控制
车辆。影子验收通过后，优先把视觉策略封装为 Nav2 控制器插件，保留动作生命周期、
速度平滑、Collision Monitor、`/cmd_vel_safe` 和底盘超时停车。

训练集必须按完整路线切分，避免相邻视频帧同时进入训练和测试造成虚高。模型需要历史
图像或显式运动状态，覆盖倒车、转向选择和短时遮挡。激光雷达不作为模型必需输入，
但继续作为独立安全源；相机断流、推理超时或模型输出非有限值时必须停车。

## 3. 开源候选与取舍

以下为官方仓库/文档核查，不等于已在本工程编译或验收。接入时固定提交或发行版，
复核 Jazzy 构建、依赖与模型权重许可，不直接追踪浮动分支。

| 项目 | 可复用部分 | 本工程决策与限制 |
| --- | --- | --- |
| [robot_localization](https://github.com/cra-ros-pkg/robot_localization) | EKF/UKF 状态估计 | 保留现有基线，补协方差、延迟、异常输入测试 |
| [RTAB-Map ROS 2](https://github.com/introlab/rtabmap_ros/tree/ros2) | RGB-D/立体/激光建图、闭环、外部 odom 接口 | 优先三维原型；官方列出 Jazzy；先旁路运行，不抢 AMCL TF |
| [FAST-LIO](https://github.com/hku-mars/FAST_LIO) | 激光惯性里程计与去畸变 | 实车 LiDAR + IMU 专项候选；官方强调逐点时间与同步，ROS 2 移植需单独核查 |
| [FAST-LIVO2](https://github.com/hku-mars/FAST-LIVO2) | 紧耦合激光、惯性与视觉里程计 | 中后期退化定位候选；官方 README 是 ROS 1/catkin 路线，不能视为 Jazzy 即插即用；仓库标注 GPLv2 |
| [Isaac ROS Nvblox](https://nvidia-isaac-ros.github.io/v/release-4.2/repositories_and_packages/isaac_ros_nvblox/index.html) | GPU 三维重建与 Nav2 地图接口 | GPU 路线备选；文档声明 Jazzy/NVIDIA 平台支持，锁定版本后实测显存；不替代位姿估计器 |
| [Grounded-SAM-2](https://github.com/IDEA-Research/Grounded-SAM-2) | 开放词汇检测、分割和跟踪 | 用于离线标注/低频语义原型；实时第一版先测轻量模型；逐个核查权重及依赖许可 |
| [ConceptGraphs](https://github.com/concept-graphs/concept-graphs) | 多视角物体融合、开放词汇三维场景图 | 借鉴物体关联和查询表示；研究管线不是完整 Nav2 导航系统 |
| [Hydra](https://github.com/MIT-SPARK/Hydra) | 实时分层三维场景图、物体/地点/房间关系 | 中后期关系语义地图候选；官方说明已切 ROS 2，并在 Ubuntu 24.04/Jazzy 测试；复杂度高于第一版需求 |
| [ViNT / NoMaD](https://github.com/robodhruv/visualnav-transformer) | 目标条件通用视觉导航、时间上下文和扩散动作生成 | 作为 V2 主候选；先复用数据表示和推理接口，再核查权重许可、ROS 2 封装与 8 GB 显存占用 |
| [LeLaN](https://github.com/robodhruv/LeLaN) | 语言条件视觉导航 | 作为 V5 候选；必须增加未知/歧义拒绝，语言模型不得绕过安全控制链 |

传感器接入参考：[Livox 官方驱动](https://github.com/Livox-SDK/livox_ros_driver2)
支持 MID-360 与 ROS 2；具体 Jazzy 构建仍需验证。
外参标定参考：[direct_visual_lidar_calibration](https://github.com/koide3/direct_visual_lidar_calibration)
提供 LiDAR–camera 标定工具和 ROS 1/ROS 2 接口；标定结果必须以独立数据验证。

近期推荐组合改为 **Nav2 老师 + 目标条件视觉策略影子运行 + 激光独立安全层**；
RGB-D 几何障碍和物体检测仍可作为安全、语义地图的并行路线，但不冒充端到端视觉
导航。RTAB-Map 为第一条三维验证路线。所有候选按需求择一评估，不同时安装。

## 5. 性能与降级策略

先给控制和安全留预算：控制 20 Hz、底盘接口 50 Hz；视觉检测先按 2–5 Hz
设计，深度障碍处理按传感器帧率评估。高负载时丢弃过期视觉帧，不阻塞控制线程。
记录端到端 P95 延迟、丢帧、实时因子、CPU/GPU/显存和内存，不只报告网络 FPS。

相机失效时暂停新增语义观测，若激光定位与安全观测健康则允许受限二维导航；
关键安全感知失效时停车，不能因为还有另一个传感器就默认其覆盖足够。
定位不确定度超限时停车/请求重定位，不把异常跳变当成已到达目标。

其他传感器按缺口加入：编码器与转角反馈优先；ToF/超声/保险杠补近距安全；
UWB 可用于室内绝对位置约束，但需基站与标定；室内不以 GNSS/磁罗盘为默认主定位。
