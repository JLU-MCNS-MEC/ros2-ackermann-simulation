# 室内速度与低速转向验证

日期：2026-09-10；基于 `424a0a5` 的运行场景和 AMCL 位姿连续测试。

## 修改

- 修复低于 0.02 m/s 时保留速度却丢弃转向的问题。默认数值静止阈值改为
  1e-6 m/s；阈值内完整停车，零阈值也不会除零。不通过增加速度实现原地转向。
- 室内导航与语义启动增加 `target_speed`，默认 0.35 m/s；旧通用导航默认不变。
- 停车区、减速区、膨胀层、减速比例和速度平滑器均未改动。

## 实际验证

在现有 Gazebo 会话中，仅重启转换器并设置控制器目标速度；未重置车辆或地图。
用 Nav2 `NavigateToPose` 连续发送以下目标，订阅导航/平滑/安全速度和 `/drive`。
单目标超时 150 s，失败停止后续目标；本次无需取消或人工接管。

| 目标 | map 坐标 x/y/yaw | 结果 | 墙钟耗时 |
| --- | --- | --- | --- |
| 中央通道 | 4.0 / 1.75 / 0 | 成功 | 38.79 s |
| 入口 | 0.18 / 0.19 / 0 | 成功 | 31.17 s |
| 办公区 | -0.37 / 5.12 / 1.57 | 成功 | 20.32 s |
| 用户点击区域复测 | 4.44 / 1.46 / 0 | 成功 | 28.93 s |
| 再回入口 | 0.18 / 0.19 / 0 | 成功 | 30.47 s |
| 再到办公区 | -0.37 / 5.12 / 1.57 | 成功 | 22.60 s |

前进输出最大 0.35 m/s，倒车仍受原有限制 0.15 m/s；有 7 个采样点确认
低于 0.02 m/s 时仍有有效转向。此次目标测试时段主日志未见 `Failed to make progress`。
第四段观察到 `PolygonSlow` 与 CLEAR 状态切换。状态消息按变化发布，采样为空
不代表安全层失效，也不能证明全程初始状态为 CLEAR。

另启动 `/safety_validation` 命名空间的 Collision Monitor，加载同一组安全区参数，
使用隔离的速度/扫描/footprint 话题，不向车辆控制链注入测试数据。
输入 0.35 m/s，合成 21 条前方雷达射线，依次持续 2 s：

1. 2.0 m：输出 0.35 m/s。
2. 0.8 m：输出 0.1225 m/s，即 35% 减速。
3. 0.5 m：输出零。
4. 恢复 2.0 m：恢复 0.35 m/s。
5. 停止扫描输入：超时后输出零。

五项均验证末尾连续 5 次输出符合预期；该测试只验证软件安全行为，不测物理制动。
核心与节点单测覆盖前后向低速、零速/零阈值、非法输入、超时停车和退出停车。
`control.py` 覆盖率 86%。构建与完整测试结果记录于交接文档。

数据：[结构化结果](data/indoor_20260910/indoor_speed_safety.json)。
现场详细采样 `/tmp/indoor_speed_validation.json`，日志 `/tmp/indoor_speed_validation.log`，
测试输入脚本 `/tmp/indoor_speed_validation.py` 和 `/tmp/indoor_safety_validation.py`。
临时文件不保证跨机器存在；上面的固定目标与隔离测试条件用于后续自动化回归。

## 限制

六次成功不是全面稳定性保证；仍需 20 次重复、动态障碍、窄道和故障注入回归。
本次未测车体净空/接触真值，不能宣称已完成零碰撞专项验收。
原用户点击目标约 106 s，但本次初始位姿和目标朝向不同，不能计算严格提速百分比。
不因本次通过而缩小安全区或增加实车速度；实车先验证总延迟和制动距离。
