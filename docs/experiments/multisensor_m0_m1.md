# M0/M1 多传感器前置验证记录

日期：2026-09-10。M0 控制配置版本 `d1a19a0`，RGB-D 工具版本 `ddadcb3`。

## M0：基线采集完成，稳定性未通过

首轮从已有办公区位姿发出目标失败。原进展检查为 10 s 内 0.5 m，低速经安全层
缩放后只有 0.0175 m/s；动作确认超时仅 20 ms。已分别改为 15 s 内 0.2 m 与
500 ms，保持巡航 0.35 m/s 和所有安全区不变。失败记录没有删除。

随后完整重启、以约 `(0.2, 0.2, 0)` 提供 AMCL 初始位姿，执行固定五目标路线。
第 18 次发生失败并按工具规则停止；检查后另发 3 个目标，均成功。
因此是 **21 次尝试、20 次成功、1 次失败**，不是连续 20 次成功。

| 指标 | 实测 |
| --- | --- |
| 成功率（本次样本） | 20 / 21，约 95.2% |
| 墙钟耗时中位数 | 26.77 s |
| 墙钟耗时 P95 / 最大值 | 77.43 s / 79.69 s |
| 累计恢复次数 | 6 |
| 目标执行墙钟总时长 | 658.83 s |
| rosbag | 4.7 GiB，740.743 s，1,007,769 条消息 |
| 控制 / 真值边界 | `/drive` 一个发布者；`/tf_ground_truth` 零订阅者 |

测试中未由本代理手动驾驶；发生失败后人工审查并启动了补充序列。其他操作者的
接管行为不由当前工具自动判定。所有目标都在同一小型场景，样本不是独立随机任务。

第 18 次失败：Collision Monitor 观察到扫描年龄超过 0.8 s 后正确停车；随后 RPP
请求 `odom -> map` 时缺少未来约 30 ms 的 TF，导致导航终止。不放宽安全源超时。

对同一 bag 的逐帧消息头离线检查进一步定位：

| 数据流 | 帧数 | 消息时间帧率 | 最大帧间隔 | bag 时间减采集时间 P95 |
| --- | --- | --- | --- | --- |
| `/scan/points` | 7,408 | 10.00 Hz | 0.10 s | 0.024 s |
| `/scan_slam` | 5,399 | 7.29 Hz | 1.20 s | 0.019 s |
| `/scan_nav` | 5,375 | 7.26 Hz | 1.00 s | 0.021 s |

说明原始雷达并未断流，缺帧出现在点云到扫描的消费/投影链路或其传输过程中。
尚不能仅凭这些数据断言是计算负载、DDS 丢包还是过滤器问题。
发布者为 RELIABLE，投影节点订阅为 BEST_EFFORT；录制节点订阅为 RELIABLE。
需进一步隔离传输和投影，不能拿原始点云频率代表导航扫描健康。

此外，RPP 的倒车指令可达 -0.35 m/s，而平滑器会独立把线速度截断到 -0.15 m/s，
角速度不按同一比例调整。该链路可能改变曲率，需独立修复和 A/B 验证。
仅启用 `scale_velocities` 不会修复绝对速度分量截断：
[Nav2 源码](https://github.com/ros-navigation/navigation2/blob/jazzy/nav2_velocity_smoother/src/velocity_smoother.cpp)
先做各分量限幅，再按加速度约束计算缩放。

小型结果：[首轮失败](data/indoor_20260910/m0_initial_failure.json)、
[21 次基线](data/indoor_20260910/m0_navigation_baseline.json)。
本地数据与有效参数快照：`artifacts/validation/20260910/m0_initial`、
`artifacts/validation/20260910/m0_baseline`，后者包含主日志 `launch.log`。

## M1：仿真数据质量验收通过

已完成关闭相机的 5 s 负向检查：零数据对，工具返回失败，未虚报通过。
启用 RGB-D 后首轮 120 s 静止检查失败：CameraInfo 约 15.15 Hz，RGB 接收约
4.71 Hz、深度约 6.67 Hz，最终只有 274 组同步数据；接收最大间隔接近 2 s。
收到的同步对时间戳一致，说明不能只检查少数配对成功的帧。

组合调整：点云桥 + 两个投影节点采用进程内通信；审核当前图像发布者为 RELIABLE
后，为检查工具增加 `--reliable`。未改变传感器频率、视场、几何过滤范围或安全门槛。
新架构/工具版本 `2318d5b`，完整重启后验证：

| 指标 | 静止 120 s | 运动 120 s |
| --- | --- | --- |
| 同步数据对 | 1,658 | 1,667 |
| 采集时刻 TF 有效 | 1,644 / 1,658 | 1,654 / 1,667 |
| RGB/深度消息时间帧率 | 约 15.15 Hz | 约 15.15 Hz |
| 同步偏差 P95 | 0 ms | 0 ms |
| 深度有效比例中位数 | 63.1% | 85.3% |
| 数据年龄 P95 | 此轮工具未采集 | 62 ms |
| 结果 | 原始门槛通过 | 含新增时效门槛全部通过 |

TF 无效仅出现在启动初期的前 14 / 13 个样本，已计入失败比例，没有删除暖机样本。
静止检查运行时工具尚未新增数据年龄门槛，不能追溯宣称该轮也验证了时效门槛。
运动检查包含连续目标执行与目标切换，不是实车全天候测试。

实测模型外参：`base_link -> rgbd_optical_frame` 平移 `(0.36, 0, 0.25) m`；
光学前/右/下分别对应车体前/右/下。内参、640 × 480 尺寸、`32FC1` 深度与模型一致。
这只验证仿真 TF/配置自洽，不能替代真实相机与激光的外参标定。

带 RGB-D 与录制负载的 5 目标全部成功、0 次恢复，耗时分别为
16.41、28.73、20.31、37.48、30.98 s。新架构 bag 为 10.6 GiB / 289.788 s；
原始点云 10.00 Hz，导航扫描 9.99 Hz、最大间隔 0.3 s，建图扫描 9.90 Hz、
最大间隔 0.5 s。比旧架构明显改善，但不能宣称完全零丢帧或已完成新的 20 次验收。

结果：[RGB-D 数据质量与导航](data/indoor_20260910/m1_rgbd_quality.json)。
原始失败和复测数据位于 `artifacts/validation/20260910/m1_initial`、
`artifacts/validation/20260910/m1_fixed`。全部 bag 的哈希在同目录层级的
`bag_sha256.txt`；大文件已通过 `.gitignore` 排除，只提交小型结果摘要。

相关两包构建通过；145 项测试通过。尚未进行自动物体检测、视觉障碍融合、
视觉里程计或三维语义建图，这些仍在后续 TODO 中。
